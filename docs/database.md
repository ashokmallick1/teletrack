# Database Architecture & PostgreSQL Migrations

## 1. Schema Overview

The database uses PostgreSQL with Row Level Security (RLS) and strict tenant isolation. All business tables reference `organizations.id` as a foreign key with cascade deletion.

## 3. Table Definitions

### 3.1 `organizations`
- `id` (UUID PK): Unique tenant ID.
- `name` (TEXT): Corporate entity name.
- `slug` (TEXT UNIQUE): URL-friendly slug.
- `timezone` (TEXT): Default timezone (e.g. `Asia/Kolkata`, `America/New_York`).
- `retention_days` (INT): Data retention policy limit (default 90 days).
- `mask_phone_numbers` (BOOLEAN): Enables masking for employee-level views.
- `max_devices` (INT): Device quota determined by subscription.

### 3.2 `devices`
- `id` (UUID PK): Internal device ID.
- `organization_id` (UUID FK): Tenant.
- `employee_id` (UUID FK): Assigned membership.
- `device_identifier` (TEXT): Persistent hardware or installation UUID.
- `device_name` (TEXT): Human readable device name.
- `model`, `manufacturer`, `os_version`, `app_version` (TEXT): Hardware specs.
- `status` (TEXT): `ACTIVE`, `PENDING_ENROLLMENT`, `SUSPENDED`, `REVOKED`.
- `last_contact_at`, `last_sync_at` (TIMESTAMPTZ): Telemetry sync timestamps.
- `permission_granted` (BOOLEAN): Current `READ_CALL_LOG` permission state.
- **Unique Constraint**: `(organization_id, device_identifier)`.

### 3.3 `call_events`
- `id` (UUID PK): Internal event ID.
- `organization_id` (UUID FK): Tenant.
- `device_id` (UUID FK): Originating device.
- `employee_id` (UUID FK): Telecaller.
- `source_call_id` (TEXT): ID generated by source dialer / log.
- `direction` (TEXT): `INCOMING`, `OUTGOING`, `MISSED`, `REJECTED`, `UNKNOWN`.
- `duration_seconds` (INT): Connected duration in seconds.
- `started_at` (TIMESTAMPTZ): Call start timestamp.
- `ended_at` (TIMESTAMPTZ): Call termination timestamp.
- `outcome` (TEXT): `ANSWERED`, `MISSED`, `REJECTED`, `BUSY`, `FAILED`, `UNKNOWN`.
- `outcome_confidence` (NUMERIC(3,2)): Confidence level of the outcome.
- `raw_phone_number` (TEXT): Unmasked phone number.
- `sim_slot`, `sim_carrier`, `phone_account` (TEXT): SIM metadata.
- `lead_id` (UUID FK): Associated lead (if auto-matched by number).
- `data_source` (TEXT): `NATIVE_CALL_LOG`, `MANUAL_ENTRY`, `CSV_IMPORT`, `TELEPHONY_API`.
- **Unique Constraint**: `(organization_id, device_id, source_call_id)`.

## 4. Row Level Security (RLS) Policy Mechanics

Every tenant table has Row Level Security enabled. When querying via Supabase or PostgreSQL client using application user claims:
```sql
CREATE POLICY call_events_access ON call_events
  FOR ALL
  USING (
    user_in_org(organization_id) OR
    EXISTS (SELECT 1 FROM profiles WHERE id = current_user_id() AND is_super_admin = TRUE)
  );
```
Server-side authorization is applied defensively in the API middleware prior to query execution to ensure multi-layered defense in depth.
